Artifact and Selection

Travlr Getaways is my MongoDB, Express, Angular, and Node.js project from CS 465. The original project was completed in August 2026; this database enhancement was prepared on October 11, 2026. I selected the same artifact used for the software design and algorithms milestones because it makes the connection between HTTP requests, application logic, and persistent data visible. The original source is preserved separately from the cumulative enhanced version.

Planned Enhancement

My approved Module One plan called for stronger persistent validation and an evidence-based review of MongoDB indexes. The earlier application validated requests at the service boundary, but a direct database write could bypass those rules. The new explicit setup script installs a collection validator with strict validation and rejection of invalid writes. It checks required fields, types, lengths, price format and bounds, coherent nights/days, and safe image filenames. Mongoose rules provide earlier feedback, while the collection validator protects native writes. MongoDB documents that validationAction controls whether an invalid document is rejected or only logged (MongoDB, n.d.-a).

Query Design

A new read-only endpoint and browser form search an exact resort and an inclusive departure-date range, with at most 100 results. The repository sorts by start date and trip code. The compound index { resort: 1, start: 1, code: 1 } follows the equality prefix with the ordered date field and a deterministic tie-breaker. MongoDB’s index-order guidance informed this design, but the actual query plan was checked rather than assuming that the index would be selected (MongoDB, n.d.-b). The pre-existing code and name indexes are retained. Price remains a validated string to preserve the existing client contract; this index does not accelerate numeric price queries or heap recommendations.

Verification and Measured Results

The isolated verification used real MongoDB 8.2.6 with 30,000 generated records and three query cases. Before the new index, the selective-month query examined 30,000 documents and used a collection scan with a blocking sort. After installation, it examined 20 documents and 20 keys to return the same 20 ordered results, using an index scan without a blocking sort. Across five explain runs per condition, the median reported execution time for this case changed from 7 ms to 0 ms. The capped full-year query examined 100 documents instead of 30,000, and the nonexistent-resort query examined zero instead of 30,000. All three before/after result lists matched.

Tradeoffs and Limits

Total reported index storage grew from 745,472 to 1,581,056 bytes in this fixture. Additional index entries must also be maintained on writes, although write throughput was not benchmarked. The experiment uses one synthetic data distribution and sequential before/after runs, so cache effects, machine load, and timer resolution limit timing conclusions. Zero-millisecond values mean the timer did not resolve the operation; they do not mean the operation was free. Examined-document counts and plan stages provide stronger evidence here than a general speedup claim. The whole response still fetches the returned documents, and broad queries require workload-specific evaluation.

Testing and Learning

All 34 backend tests passed. The database harness passed 25 checks covering direct-write rejection, duplicate codes, failed-update preservation, idempotent setup, date boundaries, query rejection, empty results, and persistence after reconnecting. A separate 17-check live regression run confirmed authenticated CRUD and the existing ranking behavior with the collection constraints installed. Chrome showed ordered search results and an explicit empty state. The Angular source is unchanged from the previously verified Module Four version; no new Angular build is claimed. The main lesson was that API validation and persistent integrity solve different problems. A second challenge was keeping legacy string fields compatible while validating their meaning. Native-write tests exposed the cases that service-only tests cannot cover.

Deployment and Security

The installer requires an explicit MONGODB_URI and is never run automatically on application startup. It audits existing records and stops if it finds invalid ones; it does not delete or silently repair them. Installation requires suitable database administration permissions and a controlled maintenance window if writers are active. Its index and validator operations are not a multi-step transaction. The deployed application should use a separate least-privilege database account without permission to bypass validation. Search parameters are allowlisted scalars, limits are bounded, returned text is safely displayed, and database connection strings are no longer printed. The inherited public registration and coarse write-permission model still require production hardening.

Original controller
const Trip = require('../models/travlr');

const tripFields = [
  'code',
  'name',
  'length',
  'start',
  'resort',
  'perPerson',
  'image',
  'description',
];

function tripPayload(body = {}) {
  return tripFields.reduce((payload, field) => {
    if (body[field] !== undefined) {
      payload[field] = body[field];
    }
    return payload;
  }, {});
}

function requiredFieldsMissing(payload) {
  return tripFields.filter((field) => (
    payload[field] === undefined
    || payload[field] === null
    || (typeof payload[field] === 'string' && payload[field].trim() === '')
  ));
}

function databaseError(res, error, action) {
  if (error?.name === 'ValidationError' || error?.name === 'CastError') {
    return res.status(400).json({ message: 'Invalid trip data', details: error.message });
  }

  if (error?.code === 11000) {
    return res.status(409).json({ message: 'A trip with that code already exists' });
  }

  return res.status(500).json({ message: `Unable to ${action} trip` });
}

function createTripsController(TripModel) {
  async function tripsList(req, res) {
    try {
      const trips = await TripModel.find({});

      if (trips.length === 0) {
        return res.status(404).json({ message: 'No trips found' });
      }

      return res.status(200).json(trips);
    } catch (error) {
      return res.status(500).json({ message: 'Unable to retrieve trips' });
    }
  }

  async function tripsFindByCode(req, res) {
    const tripCode = req.params?.tripCode?.trim();

    if (!tripCode) {
      return res.status(400).json({ message: 'Trip code is required' });
    }

    try {
      const trip = await TripModel.findOne({ code: tripCode });

      if (!trip) {
        return res.status(404).json({ message: `Trip ${tripCode} not found` });
      }

      return res.status(200).json(trip);
    } catch (error) {
      return res.status(500).json({ message: 'Unable to retrieve trip' });
    }
  }

  async function tripsAddTrip(req, res) {
    const payload = tripPayload(req.body);
    const missingFields = requiredFieldsMissing(payload);

    if (missingFields.length > 0) {
      return res.status(400).json({
        message: `Missing required trip fields: ${missingFields.join(', ')}`,
      });
    }

    try {
      const trip = await TripModel.create(payload);
      return res.status(201).json(trip);
    } catch (error) {
      return databaseError(res, error, 'create');
    }
  }

  async function tripsUpdateTrip(req, res) {
    const tripCode = req.params?.tripCode?.trim();

    if (!tripCode) {
      return res.status(400).json({ message: 'Trip code is required' });
    }

    const payload = tripPayload(req.body);
    const missingFields = requiredFieldsMissing(payload);

    if (missingFields.length > 0) {
      return res.status(400).json({
        message: `Missing required trip fields: ${missingFields.join(', ')}`,
      });
    }

    try {
      const trip = await TripModel.findOneAndUpdate(
        { code: tripCode },
        payload,
        { returnDocument: 'after', runValidators: true },
      );

      if (!trip) {
        return res.status(404).json({ message: `Trip ${tripCode} not found` });
      }

      return res.status(200).json(trip);
    } catch (error) {
      return databaseError(res, error, 'update');
    }
  }

  async function tripsDeleteTrip(req, res) {
    const tripCode = req.params?.tripCode?.trim();

    if (!tripCode) {
      return res.status(400).json({ message: 'Trip code is required' });
    }

    try {
      const trip = await TripModel.findOneAndDelete({ code: tripCode });

      if (!trip) {
        return res.status(404).json({ message: `Trip ${tripCode} not found` });
      }

      return res.status(200).json({ message: `Trip ${tripCode} deleted` });
    } catch (error) {
      return databaseError(res, error, 'delete');
    }
  }

  return {
    tripsList,
    tripsFindByCode,
    tripsAddTrip,
    tripsUpdateTrip,
    tripsDeleteTrip,
  };
}

module.exports = {
  ...createTripsController(Trip),
  createTripsController,
};

/** Chikeziri Ohaeri | CS 499 Module 5 | 2026-10-11 | v1

 * Explicit installation avoids changing an existing database on app startup.

const text = (maxLength) => ({ bsonType: 'string', minLength: 1, maxLength, pattern: '\\S' });
const asString = (field) => ({ $convert: { input: field, to: 'string', onError: '', onNull: '' } });
const numberMatch = (regex) => ({ $convert: {
  input: { $getField: { field: 'match', input: { $regexFind: { input: asString('$length'), regex } } } },
  to: 'int', onError: -1, onNull: -1,
} });
// Extract the first integer and the integer following the slash separately.
const nights = numberMatch('^[0-9]+');
const days = { $convert: { input: { $arrayElemAt: [{ $ifNull: [{ $getField: {
  field: 'captures', input: { $regexFind: { input: asString('$length'), regex: '/\\s*([0-9]+) days?$' } },
} }, []] }, 0] }, to: 'int', onError: -1, onNull: -1 } };
const numericPrice = { $convert: { input: '$perPerson', to: 'double', onError: -1, onNull: -1 } };
const validator = { $and: [
  { $jsonSchema: { bsonType: 'object', required: ['code','name','length','start','resort','perPerson','image','description'], properties: {
    code: { bsonType: 'string', pattern: '^[A-Za-z0-9_-]{1,40}$' },
    name: text(200), resort: text(200), description: text(5000),
    length: { bsonType: 'string', maxLength: 40, pattern: '^[0-9]+ nights?\\s*/\\s*[0-9]+ days?$' },
    start: { bsonType: 'date' },
    perPerson: { bsonType: 'string', pattern: '^[0-9]{1,7}(\\.[0-9]{1,2})?$' },
    image: { bsonType: 'string', maxLength: 100, pattern: '^[A-Za-z0-9_-]+\\.([jJ][pP][gG]|[jJ][pP][eE][gG]|[pP][nN][gG]|[wW][eE][bB][pP])$' },
  } } },
  { $expr: { $and: [
    { $gte: [numericPrice, 0] }, { $lte: [numericPrice, 1000000] },
    { $gte: [days, 1] }, { $lte: [days, 366] }, { $eq: [nights, { $subtract: [days, 1] }] },
  ] } },
] };
const searchIndex = { resort: 1, start: 1, code: 1 };
const searchIndexName = 'resort_start_code';
async function installConstraints(db) {
  const exists = await db.listCollections({ name: 'trips' }).hasNext();
  if (!exists) await db.createCollection('trips', { validator, validationLevel: 'strict', validationAction: 'error' });
  const collection = db.collection('trips');
  // Audit before tightening an existing collection. Never delete or silently repair data.
  const invalid = await collection.find({ $nor: [validator] }, { projection: { _id: 1 } }).limit(20).toArray();
  if (invalid.length) throw new Error('Existing trips fail validation; review and repair them before installing constraints. No records were modified.');
  await collection.createIndex({ code: 1 }, { unique: true, name: 'code_1' });
  await db.command({ collMod: 'trips', validator, validationLevel: 'strict', validationAction: 'error' });
  await collection.createIndex(searchIndex, { name: searchIndexName });
  return { indexes: await collection.listIndexes().toArray(), validationLevel: 'strict', validationAction: 'error' };
}
module.exports = { validator, searchIndex, searchIndexName, installConstraints };

function createTripsRepository(Trip) {
  return {
    // Module 5: equality prefix, date range and deterministic indexed ordering.
    search: ({ resort, from, until, limit }) => Trip.find({ resort, start: { $gte: from, $lt: until } })
      .sort({ start: 1, code: 1 }).limit(limit).lean(),
    list: () => Trip.find({}),
    find: (code) => Trip.findOne({ code }),
    create: (payload) => Trip.create(payload),
    update: (code, payload) => Trip.findOneAndUpdate({ code }, payload, { returnDocument: 'after', runValidators: true }),
    remove: (code) => Trip.findOneAndDelete({ code }),
  };
}

const { ApiError } = require('../errors/api-error');
function searchOptions(query) {
  const fail = () => { throw new ApiError(400, 'INVALID_SEARCH', 'Use an exact resort, valid from/to dates (YYYY-MM-DD), and limit from 1 to 100'); };
  if (!query || Object.keys(query).some(k => !['resort','from','to','limit'].includes(k))) fail();
  if (typeof query.resort !== 'string' || !query.resort.trim() || query.resort.trim().length > 200) fail();
  const parse = value => {
    if (typeof value !== 'string' || !/^\d{4}-\d{2}-\d{2}$/.test(value)) fail();
    const date = new Date(value);
    if (!Number.isFinite(date.getTime()) || date.toISOString().slice(0,10) !== value) fail();
    return date;
  };
  const from = parse(query.from), to = parse(query.to);
  if (from > to) fail();
  const limitText = query.limit === undefined ? '20' : query.limit;
  if (typeof limitText !== 'string' || !/^[1-9]\d{0,2}$/.test(limitText) || Number(limitText) > 100) fail();
  // Inclusive dates are implemented with an exclusive next-midnight bound.
  return { resort: query.resort.trim(), from, until: new Date(to.getTime() + 86400000), limit: Number(limitText) };
}
module.exports = { searchOptions };

const mongoose = require('mongoose');
const { installConstraints } = require('../app_api/database/constraints');
(async () => {
  if (!process.env.MONGODB_URI) throw new Error('Set MONGODB_URI explicitly to the intended database');
  try {
    await mongoose.connect(process.env.MONGODB_URI);
    const result = await installConstraints(mongoose.connection.db);
    console.log(JSON.stringify({ installed: true, indexNames: result.indexes.map(x => x.name) }));
  } finally { await mongoose.disconnect(); }
})().catch(error => { console.error(error.message); process.exitCode = 1; });
